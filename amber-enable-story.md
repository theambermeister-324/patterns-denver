# Amber's Morning Story — The Enable Story
**Patterns Denver · June 11, 2026**
*3–4 minutes. First-person. Goes after anonymous cards are read back, before Aaron's story.*

## The version to tell

We had a problem that every sales team has: the work that gets deals done — the time-to-value doc, the strategic playbook, the QBR — takes a full day to build, and it needs to be done well, for every client, every time.

So we built a toolkit. We called it Enable.

It runs entirely in the terminal, using Claude Code — the same tool you're about to use this afternoon. You type a command, name a client, and it generates a complete client-facing deliverable: a time-to-value document, a playbook, a quarterly business review. Formatted, on-brand, ready to hand over.

The input is a YAML file with the client's data. The output is something that would have taken a skilled person half a day to write.

What surprised me was how fast the ceiling moved. The first version was just "generate this document." Then we started asking it harder questions — *What's the pattern across all our clients? Which deals share the same friction points? What should we say to a pharma company that we wouldn't say to a bank?* And it could answer those questions. Because the data was structured. Because we'd given it something real to work with.

That's the moment I want you to hold onto today.

**Your design system already has structure.** It has components with props and usage rules and variants. It has tokens that mean something. It has decisions someone made three years ago that nobody wrote down but everybody follows. That is a knowledge base. And if you give an AI agent access to it, it can start answering questions that right now only a human can answer — "When should I use the ghost button variant?" "What are the accessibility gaps in our form components?" "What would a new engineer need to know that isn't in our docs?"

That's the prompt on the screen when you sat down. That's the first thing worth automating.

We didn't build Enable to replace our sales team. We built it so our sales team could do better work, faster, without starting from a blank page every time.

You're here today to find your version of that.
