Where the time leaked (avoidable rework)

  1. orderSCSS imported before it was written — App.tsx imported ./App.scss before the file existed → stale Vite errors I had to disambiguate from live ones.
  2. guessNon-existent Carbon class — used cds--type-fluid-heading-06 (doesn't exist) → corrected to -05.
  3. churnFonts redone 3× — aggregate @ibm/plex CSS pulled every Plex family into dist → hand-rolled fonts.scss (3 weights) → disabled Carbon's broken ~@ibm/plex font-faces ($css--font-face:false).
  4. docsDoc-lookup thrash — the docs MCP hit its monthly quota and a Carbon WebFetch returned truncated; fell back to reading node_modules (reliable, but cost cycles).
  5. deployNetlify pnpm→npm — first Git build failed: Netlify defaulted to pnpm, whose strict node_modules broke Carbon's loadPaths:['node_modules']. Fixed (commit 86b0706) by declaring @carbon/styles directly + tracking a lockfile to force npm.
  6. verifyRound-trips — a vite.config change forced a dev-server restart, plus several screenshot/inspect cycles.

What worked (keep doing)

  • winPre-emptive Sass config (loadPaths + quietDeps + silenceDeprecations) avoided the #1 Carbon-on-Vite time-sink.
  • winVerify-the-pipeline-first (one styled <Button>) caught wiring before the full build.
  • winThe content.ts content↔presentation seam — already pays off for Phase 2.
  • winReading node_modules for ground truth when the docs failed.

Efficiency recommendations for Phase 2

1. Codify, don't re-plan

Turn Phase 1's decisions into a fixed-context CARBON_BUILD.md (component names, real type classes, config facts, the rework rules). The 6 pages become mechanical — no per-page deliberation.

2. Build once, reuse

Extract a PageShell (header/nav/footer/Theme); useState + hash routing (no react-router); extend content.ts to a typed block model so pages are dumb renderers.

3. Pre-solve the 2 gaps

Prompts → Carbon CodeSnippet (built-in copy button); Feedback → wrap the survey iframe in a Tile. Don't hand-roll either.

4. Docs = node_modules

Resolve every component/type-class name from one .d.ts read. Skip the docs MCP (quota) and WebFetch (truncates).

5. Measure + budget

Set a token budget; capture per-page tokens / rework / time-to-rubric. The proof of the thesis is page 6 costing far less than page 1.

6. Verify once

One screenshot sweep across all 7 pages at the end; freeze vite.config (no restarts); automate the rubric.

🏛️ Council verdict — Phase 2

Agreement (high confidence)

The build was never the problem — re-deciding settled questions was. Don't run another big council. Codify into a build doc, extract a PageShell once, model content as typed data, pipeline foundation-then-batch, verify once.

The clash

How much to build beyond the 6 pages. The Expansionist wanted instrumentation + a switcher harness + a productized offering now; the majority (Contrarian, First Principles, Outsider) called that premature abstraction tax. Synthesis: light metrics yes, switcher/productization deferred.

Blind spots caught

Unmeasured build-token baseline (no tokens-per-page denominator); Phase 1 deploy status; no token budget set.

The one thing to do first: write CARBON_BUILD.md from a single node_modules pass before any page work.

Decisions taken

Scope → Lean 6 pages + light metrics. Defer the switcher harness & productization.
Deploy → Build now, deploy in parallel (Netlify Git auto-build ships each push to carbon-redesign).
