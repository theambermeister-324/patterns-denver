🏛️ LLM Council Verdict

Workshop app experience — enhancement recommendations

How do we make the Patterns Denver 2026 companion app best-in-class, benchmarked to high-quality hands-on / sandbox workshops? (Afternoon in-person; attendees run Claude Code in their own terminal on their own docs; Carbon SPA + Supabase; Knapsack's goal: make practitioners feel their docs aren't AI-ready → convert to a PCRI assessment.)
2026-06-12 · 5 advisors · anonymized peer review · benchmarked vs Instruqt, Qwiklabs, GitHub Skills, Scrimba, Stripe/Twilio onboarding

The roadmap (prioritized)

Tier 0 — Guide rails · ship next workshop (~weekends, pure frontend)
  • Persistent progress + "you are here": localStorage Setup checklist, global ProgressIndicator (Step X of Y), copy-✓ per snippet, per-page complete.
  • Anti-stuck rails on Playbook: per-command "fill in YOUR part" callouts, expected-output screenshot/GIF, inline "didn't work?" fix, and a persistent "Stuck?" affordance on every page.
  • Pin "your sentence" across Playbook + Prompts so the attendee's own goal follows them.
  • Offline-capable pages (conference wifi dies), a time-boxed agenda, and a done-early / falling-behind path.
Tier 1 — The conversion core (the actual point)
  • In-room AI-readiness score from running Claude on their own docs — a surprising number is the conversion (the "show their data" move).
  • Bind sentence → score → PCRI as one consented identity thread (a funnel, not 7 pages).
  • An in-room "start your PCRI / talk to us" path + warm AE handoff — don't defer the highest-intent moment to a 48h email.
  • Consent & privacy first-class — opt-in before any capture; local-by-default. Proprietary docs are involved; this gates the whole funnel.
Tier 2 — Compounding & distribution
  • Gallery as permanent, shareable artifacts: per-result permalinks + OG image ("I audited my design system at Patterns Denver…"), ranked by "biggest gap found", live counter on every page.
  • Bring the Supabase gallery + survey natively into Carbon (kills the link-out).
  • 48h follow-up email with their result + "run this on your real repo" + PCRI CTA; Slack cohort as a standing community.
  • Workshop-in-a-box: a re-skin/config layer (content's already decoupled) to redeploy per conference / enterprise team.
Tier 3 — Resilience (right-sized, NOT a rebuild)
  • A pre-seeded repo / Codespaces devcontainer link for the broken-laptop case — fallback only, not a hosted sandbox (that breaks the BYO-terminal premise).
  • Optional facilitator view of room progress (piggyback the Supabase wall).

Council verdict

Where the council agrees

  • Today the app is a table of contents, not an experience — the missing layer is guide rails (where am I, am I stuck, did it work).
  • It's conversion instrumentation for an in-room "felt gap" → PCRI, not an LMS.
  • The Gallery is the underused engine — social proof in-room, distribution after.
  • Don't build an in-browser terminal / hosted sandbox — BYO-terminal-on-own-docs is the advantage, not a gap.

Where the council clashes

Reliability vs. premise. The Contrarian wants a hosted environment so a broken laptop ≠ a broken attendee; First Principles + Executor say that guts the value prop. Resolution: keep BYO, add a right-sized fallback (pre-seeded repo / Codespaces + offline-capable pages), not a rebuilt sandbox.

Blind spots the peer round caught

  • Consent / privacy on proprietary docs — gates whether the funnel is usable at all.
  • In-room live conversion — the highest-intent moment is in the room, not a 48h email.
  • Mixed-skill pacing — a path for early finishers and those falling behind.

The recommendation

Treat the app as a consented funnel: ship Tier-0 guide rails by the next workshop, then build the Tier-1 conversion core (readiness score + sentence→score→PCRI thread + in-room CTA + consent). Tier 2 makes it compound and re-deployable; Tier 3 keeps it resilient without betraying the BYO premise.

The one thing to do first: define the success metric — % of attendees who start a PCRI within 72h — and instrument the single thread sentence → readiness score → PCRI, with explicit consent. Everything else serves that or is polish.

Advisor responses

First Principles It's a conversion event, not an LMS

Sandbox-provisioning exemplars solve a problem you don't have — BYO-terminal-on-own-docs is the unfair advantage. Make the gap measurable in-room (a readiness score on their own docs — the surprising number is the conversion); bind sentence → score → follow-up as one thread; Gallery ranked by "biggest gap found". Cut gamification/badges/terminals. Metric: % who start a PCRI within 72h.

Expansionist A distribution asset treated as a handout

The Gallery is the product — permanent shareable artifacts + OG images ("I audited my design system at Patterns Denver"), mint findings not badges. "Sentence → result" is a repeatable funnel → workshop-in-a-box, re-skinnable per conference. Post-event: 48h result email + "run on your real repo" + PCRI CTA; Slack cohort as a standing community. It's Knapsack's top-of-funnel demand engine disguised as a workshop.

Outsider The terminal is scary; the site pretends it isn't

Add a screenshot/GIF of the terminal after each command (incl. success). Copy-paste betrays — add "fill in YOUR part" + "what if it didn't work" under each command. Progress trail ("Step 2 of 4") + time estimates. Pin the Setup "sentence" atop Playbook & Prompts. Live counter ("14 things made") on every page. A "Stuck? common fixes" panic button everywhere — never a dead end.

Executor Ranked by effort, all shippable

Weekend wins: localStorage Setup checklist; global progress indicator; copy-✓ per CodeSnippet; per-page complete + deep links. Week: pull the Supabase gallery + survey natively into Carbon (supabase-js already available) — kills the link-out, live wall = social proof. Trap: in-browser terminal/real sandbox — breaks the premise, month+ infra. Ship 1–4 next workshop, 5 after.

Contrarian A beautiful table of contents needs guide rails

Confuses "companion" with "sandbox" — will fail live when 30 unmanaged laptops run /setup (Node drift, proxies, no-admin, expired auth). Ship a hosted/browser fallback. No progress/correctness validation (GitHub Skills/freeCodeCamp validate; Qwiklabs scores) — add self-checkpoints + a facilitator dashboard. The "sentence" is collected nowhere measurable. Missing: offline mode, a time-boxed agenda, a "raise a flag → human" path.
