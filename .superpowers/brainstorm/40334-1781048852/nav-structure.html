How should the site be structured?

Three valid approaches — each affects how participants navigate and how we build it.

A — Multi-page site Recommended

5 separate HTML files linked by a shared nav bar. Each section is its own page — easy to bookmark ("open prompts on my phone"), easy to build one page at a time, matches the existing gallery structure.

Pros

  • Bookmarkable sections
  • Fastest to build
  • Matches existing code

Cons

  • Full page reload on nav

B — Single page, tab switcher

One HTML file. JavaScript swaps visible sections instantly — no page reloads. Tab pills at the top act as navigation. Feels more like an app. State could persist in localStorage (e.g., remember which step they're on).

Pros

  • Instant switching
  • Single file to deploy
  • Can track progress

Cons

  • Not bookmarkable by section
  • More JS complexity
PATTERNS DENVER 2026

C — Single long-scroll page

Everything on one page: hero → before → day-of guide → prompts → gallery → after. Anchor links in nav jump to each section. Simple, no JS required, works perfectly on mobile too.

Pros

  • Zero JavaScript
  • Mobile-perfect
  • Easiest to build

Cons

  • Long scroll during workshop
  • Can't anchor-bookmark easily
